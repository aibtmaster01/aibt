# 기능정의서 (Feature Specification)

> **목적**: 각 기능의 입력·처리·출력·로직·데이터 흐름·화면 이동을 상세 기술. AI 에이전트가 로직·플로우를 재구현하거나 검증할 때 참조.  
> **범위**: 실서버 기준. 베타 전용 기능은 "(실서버 추후 구현 예정)" 표기.

---

## 1. 인증·회원

### 1.1 로그인

- **입력**: 이메일·비밀번호 또는 구글 OAuth.
- **처리**:
  - Firebase Auth `signInWithEmailAndPassword` 또는 `signInWithPopup`(Google).
  - 로그인 성공 시 Firestore `users/{uid}` 문서 조회. 없으면 `ensureAppUserFromFirebaseUser`로 생성(기본값: isAdmin false, memberships 등 빈 값).
  - 문서에서 `isAdmin`, `memberships`, `paidCertIds`, `expiredCertIds`, `subscriptions` 등 읽어 클라이언트 `User` 객체 구성.
- **출력**: 전역 `user` 상태 갱신. 의도(intent)에 따라 다음 화면 결정.
- **이동 경로**:
  - 일반: `/mypage` 또는 `/`.
  - 관리자(isAdmin): `/` 또는 `/admin`에서 관리자 대시 렌더.
  - 퀴즈 이어하기: 로그인 모달 intent가 guestContinue면 퀴즈 재개.
  - 결제 유도: intent가 checkout이면 `/checkout`.
- **예외**: 잘못된 비밀번호·미인증 이메일 등 → 에러 메시지 표시. (실서버: 이메일 미인증도 로그인 허용 가능.)

### 1.2 회원가입

- **입력**: 이메일·비밀번호·이름(성/이름 또는 단일 이름).
- **처리**: Firebase Auth `createUserWithEmailAndPassword`. 이메일 인증 발송(정책에 따라). Firestore `users/{uid}` 생성(created_at, email, name, isAdmin false, memberships 등).
- **출력**: (이메일 인증 대기 시) 안내 문구. (즉시 로그인 허용 시) user 갱신 후 대시 또는 OT(베타, 실서버 추후).
- **이동 경로**: 로그인과 동일. 베타: 신규는 onboardingStatus 0 → OT(업데이트 안내·레벨·오티·쿠폰) → 완료 후 「가입 완료」 팝업 1회 → `/exam-list`.

### 1.3 로그아웃

- **처리**: Firebase Auth `signOut`. 전역 `user` null.
- **이동 경로**: `/`(랜딩). 모달이 열려 있으면 닫기.

### 1.4 온보딩(베타, 실서버 추후 구현 예정)

- **트리거**: 로그인 성공 후 `onboardingStatus` 0(신규) 또는 1(기존·레벨 미선택). 프리미엄+레벨 선택 완료(2)면 OT 스킵.
- **단계**:
  1. 업데이트 안내(선택): 문구·버튼 「새로운 진단 시작하기」 → 레벨 단계로.
  2. 레벨 선택: 초급(l)/어느 정도(m)/많이(h). 저장 시 `prepLevel` → Firestore. 진단 1회차 제출 시 초기 Elo 반영.
  3. 오티 슬라이드: 학습 vs 실전, 맞춤형 모의고사, 대시보드 소개.
  4. 쿠폰 입력(신규 등): 쿠폰 코드 입력 → redeem → memberships 갱신.
- **완료 시**: `onboardingStatus` 2로 갱신(해당 시). `setShowOrientationPopup(null)`, navigate `/exam-list`. 신규(0)일 때만 「회원 가입 완료」 팝업 1회 후 `/exam-list`.

## 2. 모의고사·회차

### 2.1 자격증·회차 목록 조회

- **입력**: (선택) 쿼리 `cert`(자격증 ID). 없으면 사용자 구독/멤버십에서 기본 자격증.
- **처리**: `EXAM_ROUNDS`(또는 동적 라운드)에서 해당 자격증의 1~3회차(고정)·4회차~(맞춤형) 목록 생성. `checkExamAccess`로 회차별 잠금/이용 가능 판단. 완료 여부는 `exam_results` 또는 캐시에서 회차별 제출 이력 조회.
- **출력**: 회차 카드 배열(roundId, 제목, 문항 수, 잠금, 완료).
- **이동 경로**: 카드 클릭 → 모드 선택 모달 → (4회차 이상) 5초 오버레이 + 큐레이션 → `/quiz`.

### 2.2 회차 접근 제어(checkExamAccess)

- **로직**:
  - Guest: 1회차만 UI에서 20문항 제한. 2회차 이상 차단.
  - Free: 1·2회차 허용. 3회차 시도 시 `reason: '열공모드로 합격권에 진입하세요.'` → 결제 유도 모달.
  - Premium: 전 회차 허용.
  - Expired: 전 회차 차단(오답노트만 안내 등).
  - Admin: 해당 자격증 문항 있으면 전 회차 허용.
- **반환**: `{ allowed: boolean, reason?: string }`.

### 2.3 문항 로드(고정형 1~3회차)

- **입력**: certId, round(1|2|3), user.
- **처리**:
  - `users/{uid}/user_rounds/{round}` 존재 시 저장된 `questionIds`로 문항 fetch.
  - 없으면 인덱스에서 `metadata.round === round` 필터 → 과목·core_id 순 정렬 후 needCount(예: 80)개 q_id 선정 → `fetchQuestionsFromPools(certCode, qIds)`. 로그인 유저면 `user_rounds`에 questionIds 저장(기존 없을 때만).
- **출력**: Question[] → preFetchedQuestions로 Quiz에 전달.

### 2.4 문항 로드(맞춤형 4회차~)

- **입력**: certId, round(4 이상 또는 라운드 99 라벨), user, (선택) questionCount(40|80).
- **처리**:
  - 인덱스에서 **라운드 99 풀**만 사용. `aiRoundCurationService.selectQuestionIdsBy3ZonesPerSubject`: 과목당 20문항(1구역 12 + 2구역 8). 제외 집합: 직전 N회 맞춤형 회차의 questionIds. 동일 core_id/sub_core_id 중복 제한(MAX_PER_CORE_ID, MAX_PER_SUB_CORE_ID). calcScore: 약점·트렌드·난이도 적합도·취약 유형 보너스·희소 페널티.
  - 선정된 80(또는 40)개 q_id로 Firestore에서 문항 본문 로드. `user_rounds`에 questionIds 저장(기존 없을 때만).
- **출력**: Question[] → preFetchedQuestions.

## 3. 퀴즈·채점

### 3.1 퀴즈 진행(학습/실전 모드)

- **학습 모드**: 문항별 제출 → 즉시 채점 → 정답/오답·해설·wrong_feedback 표시. 「모르겠어요」 선택 시 selected=0. 「헷갈려요」 체크 시 닫을 때 isConfused 플래그.
- **실전 모드**: 모든 문항 풀이 후 일괄 제출. 채점 시 문항별 elapsedSec으로 isConfused(elapsedSec ≥ estimated_time_sec×2.5), isLucked(정답이고 Expected<0.5이고 elapsedSec < estimated×0.5) 판정.
- **제출 시**: sessionHistory(문항별 qid, 선택, isCorrect, elapsedSec, isDontKnow, isConfused, isLucked)와 questions 배열을 `gradingService.submitQuizResult`에 전달.

### 3.2 채점·저장(submitQuizResult)

- **입력**: uid, certId, sessionHistory, questions, options(roundId, roundLabel, examId, prepLevel 등).
- **처리**:
  1. certification_info 로드 → 과목별 배점·과락선.
  2. 과목별 점수 계산(subject_scores). 최저 과목 점수로 과락·합격 여부(is_passed).
  3. 예측 합격률: computePredictedPassRate(subject_scores, minSubjectScore) → 시그모이드·클램프(15~96%).
  4. `users/{uid}/exam_results/{examId}` 저장: certCode, roundId, roundLabel, subject_scores, is_passed, predicted_pass_rate, totalQuestions, correctCount, answers, submittedAt.
  5. `users/{uid}/stats/{certCode}` 갱신: core_concept_stats, problem_type_stats, subject_stats, sub_core_id_stats, tag_stats에 correct/total 누적 + proficiency(Elo) 갱신. getWeightMultiplier(isDontKnow, isConfused, isLucked, isCorrect)로 Elo 변동량 가중. confused_qids, dontknow_qids 리스트 갱신.
  6. (선택) problem_attempt_stats 문항별 집계.
- **출력**: examId, subject_scores, is_passed. 클라이언트는 `/result`로 이동하고 result 화면에서 examId·점수·합격률 표시.

### 3.3 예측 합격률 표시

- **회차 결과**: 해당 exam_result의 `predicted_pass_rate` (3회차부터 저장됨).
- **대시보드**: 최근 3회 진단 시험의 predicted_pass_rate 가중 평균(weights 0.2, 0.3, 0.5). 3회 미만이면 진행률만 표시.

## 4. Elo·통계

### 4.1 Elo(proficiency) 구조

- **저장 위치**: `users/{uid}/stats/{certCode}`. core_concept_stats, problem_type_stats, subject_stats, sub_core_id_stats, tag_stats 각 키별로 `correct`, `total`, `proficiency`(1200 기준, K=32).
- **갱신**: 채점 시 문항별로 해당 개념·유형·과목·태그 키에 대해 nextProficiencyWithWeight(기존 proficiency, 문제 난이도 Elo, 정답 여부, 가중치) 적용. 가중치: isDontKnow 1.3, isConfused 오답 1.1 정답 0.4, isLucked 정답 0.2 등.
- **표시**: eloToPercent(proficiency) → 0~100%로 변환. 대시보드·관리자 학습현황에서 "현재 Elo(이해도 %)"로 표시.

### 4.2 집중학습(과목 강화·취약 유형·취약 개념)

- **진입**: 마이페이지 버튼 → 모드 선택 모달 → 5초 오버레이.
- **문항 수**: 각 50문항(또는 정책값). fetchSubjectStrengthTraining50, fetchWeakTypeFocus50, fetchWeakConceptFocus50. stats의 subject_stats·problem_type_stats·core_concept_stats 기반으로 취약/커버리지 영역에서 선정.
- **이동 경로**: 준비 완료 후 `/quiz`(roundLabel만 별도, roundId 특수값). 제출 후 동일하게 exam_results·stats 반영.

## 5. 결제·쿠폰

### 5.1 결제(실서버)

- **플로우**: `/checkout`에서 상품(회차 이용권) 선택 → (구현 시) PG 결제 → 결제 완료 콜백에서 setPaymentComplete·memberships 갱신 → paidCertIds 반영.
- **이동 경로**: 결제 완료 후 `/exam-list` 또는 `/mypage`.

### 5.2 쿠폰(베타, 실서버 추후 구현 예정)

- **입력**: 쿠폰 코드.
- **처리**: Firestore `coupons/{code}` 조회. 유효(미사용·만료 전·자격증 일치) 시 redeem → `users/{uid}.memberships`에 해당 자격증 PREMIUM·expiry_date 등 갱신. used_by 또는 사용 이력 기록.
- **출력**: refreshUser 후 isPremium·paidCertIds 갱신. UI에서 유료 회차 잠금 해제.

## 6. 관리자

### 6.1 관리자 판별

- **조건**: Firestore `users/{uid}.isAdmin === true`. (현재: 호스트 무관. 과거에는 실서버 호스트에서만 노출 옵션 존재.)
- **접근**: `/admin`, `/admin/certs`, `/admin/questions`, `/admin/billing`. canShowAdmin(user)가 true일 때만 Admin 컴포넌트·하위 라우트 렌더. 아니면 Access Denied 또는 리다이렉트.

### 6.2 회원 목록·학습현황

- **회원 목록**: Firestore `users` 컬렉션 orderBy(documentId()) limit(20) + 페이지네이션. 검색(이메일·이름)·필터(상태·자격증). 행별: 수기 결제/권한 수정, 학습현황 확인하기, 메모, 비밀번호 재설정, 기기 초기화, 이용 정지/해제.
- **학습현황**: 선택한 uid에 대해 `fetchUserExamResultsForAdmin(uid)` → `users/{uid}/exam_results` orderBy submittedAt asc(또는 desc 후 역순). 회차별 roundLabel, 점수(과목 평균 또는 정답률), predicted_pass_rate(3회차부터), submittedAt. `fetchUserStatsForAdmin(uid, certCode)` → subject_stats 등 proficiency → Elo % 표시.

### 6.3 수기 결제/권한 수정

- **처리**: 선택 자격증별 tier(PREMIUM)·start_date·expiry_date·target_schedule_id를 폼으로 수정 → updateUserMemberships(uid, updates). Firestore `users/{uid}.memberships` 갱신.

### 6.4 문제 관리

- **기능**: 자격증·회차·과목 필터. 문항 목록(고유값·개념명·테이블 O/X·이미지). 문항 수정(지문·선택지·정답·이미지)·저장. Firestore `certifications/{certCode}/question_pools/.../questions/{qid}`.

### 6.5 쿠폰 등록/폐기

- **등록**: AdminBilling에서 쿠폰 코드·자격증·유효기간 등 입력 → Firestore `coupons/{code}` setDoc.
- **폐기**: 문서 삭제 또는 used 플래그. (실서버 추후 구현 예정 시 동일 스펙 적용.)

## 7. 화면 이동 경로 요약

| 액션 | 출발 | 도착 |
|------|------|------|
| 무료 진단 시작 | `/` | `/exam-list` |
| 회차 선택 후 퀴즈 | `/exam-list` | `/quiz` |
| 퀴즈 제출 | `/quiz` | `/result` |
| 결과에서 다시 풀기 | `/result` | `/quiz` |
| 결과에서 다음 회차 | `/result` | `/exam-list` |
| 결과에서 대시보드 | `/result` | `/mypage` |
| 결과에서 결제 | `/result` | `/checkout` |
| 마이페이지에서 모의고사 | `/mypage` | `/exam-list` |
| 마이페이지에서 집중학습 | `/mypage` | (모달·오버레이) → `/quiz` |
| 로그인 성공(일반) | 모달 | `/mypage` 또는 `/` |
| 로그인 성공(관리자) | 모달 | `/`(Admin 렌더) 또는 `/admin` |
| OT/쿠폰 완료(베타) | 팝업 | `/exam-list` |
| 결제 완료 | `/checkout` | `/exam-list` 또는 `/mypage` |

*기능정의서는 로직·데이터 흐름·이동 경로를 코드에 가깝게 기술함. 화면 레이아웃은 화면정의서, 정책(등급·접근)은 회원정책 참고.*
