# 베타 2.0 업데이트 안내 팝업 · 베타 실서버 배포 계획

> 요구사항 정리 + 로컬 → 베타 실서버 적용을 위한 계획. **구현은 별도 단계에서 진행.**

---

## 1. 요구사항 이해 정리

### 1.1 사용자 타입 정의

| 타입 | 정의 | 안내 팝업 |
|------|------|------------|
| **A** | 로그인 후 쿠폰 가입만 한 사람 (유료 전환됐지만 **아직 문제를 풀지 않음**) | 로그인 후 **즉시** 업데이트 안내 팝업 |
| **B** | 로그인 후 쿠폰 입력하고 **문제까지 푼 사람** | 로그인 후 **즉시** 업데이트 안내 팝업 |
| **C** | 아직 비로그인 사용자 | **업데이트 안내 팝업 없음**. 가입 후 흐름만 제공 |

- A/B 구분: **시험 응시 이력 유무** (`exam_results` 존재 여부 또는 `fetchHasAnyExamRecord`)로 판단.
- A·B 모두 **동일한** 업데이트 안내 팝업을 **로그인 직후 1회** 노출.

### 1.2 업데이트 안내 팝업 (타입 A·B 전용)

- **크기**: 오리엔테이션 모달과 동일.
- **제목**: `🎉 핀셋 베타 2.0 - 더 똑똑해졌어요!`
- **본문 요약**:
  - 베타 테스터 피드백으로 AiBT 진화.
  - 새 기능: 진단 50% 단축(240→120문항), 내 수준 맞춤 진단, 문제 신고, 합격률 예측·과목별 시각화 개선.
  - 합격률은 실력 확인 모의고사 3회 풀면 제공.
  - **데이터 초기화 안내**: 베타테스트 기간 푼 문제 데이터 초기화, 양해 부탁, 새 진단에서 더 정교한 분석 제공.
- **버튼**: `[ 새로운 진단 시작하기 ]`
- **버튼 클릭 시 플로우**  
  `업데이트 안내 모달 닫기` → **난이도 선택 모달** → **오리엔테이션 모달** (쿠폰 입력 없음, LNB 스타일) → **마지막 슬라이드(응원 문구)** → 닫기.

### 1.3 버튼 클릭 후 플로우 상세

1. **업데이트 안내 모달**에서 `[ 새로운 진단 시작하기 ]` 클릭 → 모달 닫기.
2. **난이도 선택 모달** 표시 (초급/중급/고급) → 선택 시 `prepLevel` 저장 등 기존 로직.
3. **오리엔테이션 모달** 표시  
   - **쿠폰 입력 단계 없음** (이미 쿠폰 등록된 A·B이므로).  
   - `fromLNB`와 같은 모드: 슬라이드만 보여주고, **마지막 페이지**에서 “LNB 스타일” 응원 문구 노출.
4. **마지막 페이지(응원 문구)**  
   - “모든 학습자님들의 12회 빅데이터분석기사 필기 시험 합격을 기원합니다!”  
   - “사용하시며 궁금하신 내용이나 발견한 오류 혹은 기대하시는 점들을 개발자에게 알려주세요!”  
   - “카카오톡 @aibt_beta”  
   - **닫기** 버튼으로 종료.

즉, **업데이트 안내 → 난이도 선택 → 오티(쿠폰 없음) → 응원 문구 → 닫기** 순서로만 진행.

### 1.4 타입 C (비로그인)

- **업데이트 안내 팝업 없음.**
- 가입 후 플로우는 **현재 로컬 서버와 동일** 유지:  
  **가입(로그인)** → **난이도 선택** → **오리엔테이션 모달** → **쿠폰 입력** → 서비스 이용.

## 2. 적용 환경 구분

- **베타 실서버**: `import.meta.env.DEV === false` 이고 `APP_BRAND === 'AiBT'` (또는 베타 빌드).  
  → 여기서만 **A·B에게 업데이트 안내 팝업** 노출.
- **베타 로컬**: `isBetaLocal === true`.  
  → 타입 C와 동일하게 **업데이트 안내 없이** 기존 플로우(가입 → 난이도 → 오티 → 쿠폰) 유지 가능하거나, 필요 시 “베타 2.0 안내” 노출 여부를 플래그로 분리.

정리: **업데이트 안내 팝업은 “베타 실서버 + 로그인 + 쿠폰 보유(A 또는 B)”일 때만, 1회 노출**하는 것으로 이해.

## 3. 로컬 → 베타 실서버 적용을 위한 계획

### 3.1 코드/리소스 반영 (배포물)

| 항목 | 내용 | 비고 |
|------|------|------|
| 빌드 | `npm run build:beta` 등 베타 빌드 산출물 | 현재 로컬과 동일 소스 기준 |
| 호스팅 | Firebase Hosting 등 베타 프로젝트에 배포 | 기존 배포 스크립트 활용 |
| Firestore 규칙 | `firestore.rules` (certifications_beta, users 등) | 로컬과 동일 규칙 적용 여부 확인 |
| 환경 변수 | 베타 실서버용 `VITE_APP_BRAND=AiBT` 등 | DEV=false, FEATURE_COUPON 등 필요 시 설정 |
| 인덱스/문항 | `certifications_beta` (BIGDATA 레벨드 인덱스, 문항) | 로컬에서 사용 중인 것과 동일 버전 업로드 |

### 3.2 신규 구현 (베타 2.0 안내)

| 단계 | 작업 | 담당 시점 |
|------|------|-----------|
| 1 | **업데이트 안내 모달 컴포넌트** 추가 (오리엔테이션과 동일 크기, 제목/본문/버튼). 본문은 위 1.2 내용 반영. | 구현 단계 |
| 2 | **노출 조건**: 베타 실서버 + 로그인 + `hasCoupon` + “아직 이번 업데이트 안내를 보지 않음”(세션/로컬 플래그 또는 서버 플래그 1회). A/B 구분은 동일 팝업이므로 불필요할 수 있음. | 구현 단계 |
| 3 | **`[ 새로운 진단 시작하기 ]` 클릭 시**: 업데이트 모달 닫기 → 난이도 선택 모달 열기 → 선택 시 오리엔테이션 모달 열기 (`fromLNB` 스타일, 쿠폰 페이지 없음) → 마지막에 응원 문구 + 닫기. | 구현 단계 |
| 4 | **난이도 선택**: 기존 난이도 선택 UI/로직 재사용 (OrientationPopup 또는 별도 모달). | 구현 단계 |
| 5 | **오티 “fromLNB” 모드**: 쿠폰 입력 없이 슬라이드만 진행, 마지막에 “응원 문구 + @aibt_beta + 닫기”만 노출. (이미 LNB용 응원 문구 있음) | 구현 단계 |

### 3.3 데이터/초기화 (이미 공지한 경우)

- “베타테스트 기간 푼 문제들의 데이터는 초기화되었음”은 **운영 정책** 안내 문구이므로, 실제 초기화는 별도 배치/수동 작업으로 이미 했다고 가정.
- 앱 코드는 **기존 경로** 그대로 사용: `users/{uid}/exam_results`, `users/{uid}/stats/{certCode}` 등. 초기화 후 빈 상태로 두면 A·B도 “새로운 진단 시작” 플로우로 자연스럽게 진입.

### 3.4 체크리스트 (배포 전)

- [ ] 베타 빌드(`build:beta`) 성공 및 정적 자산 확인
- [ ] 베타 Firebase 프로젝트 연결 및 호스팅 배포
- [ ] Firestore 규칙·인덱스가 베타 실서버에 적용되어 있는지 확인
- [ ] `certifications_beta` 인덱스/문항이 실서버에 업로드되어 있는지 확인
- [ ] 업데이트 안내 팝업 컴포넌트 구현 및 “베타 실서버 + 로그인 + 쿠폰” 조건에서만 1회 노출되도록 연동
- [ ] [ 새로운 진단 시작하기 ] 클릭 시 **학습 이력만 초기화**(쿠폰/유료 정보 유지) API 호출 후 플로우 진행
- [ ] [ 새로운 진단 시작하기 ] → 난이도 → 오티(LNB 스타일) → 응원 문구 → 닫기 플로우 검증
- [ ] 타입 C: 비로그인 시 팝업 없음, 가입 후 난이도 → 오티 → 쿠폰 순서 유지 확인
- [ ] (선택) 로컬에서는 업데이트 안내를 끄고, 베타 실서버에서만 켜는 플래그 정리

## 4. 요약

- **A·B**: 로그인 후 즉시 **한 번만** “베타 2.0 업데이트 안내” 팝업(오리엔테이션과 동일 크기) → `[ 새로운 진단 시작하기 ]` → 난이도 선택 → 오티(쿠폰 없음) → 응원 문구(@aibt_beta) → 닫기.
- **C**: 업데이트 안내 없음. 가입 후 **난이도 선택 → 오티 → 쿠폰 입력** 순서 유지.
- **배포**: 현재 로컬 베타와 동일한 코드/리소스를 베타 실서버에 반영하고, 위 신규 구현(업데이트 안내 + 플로우)만 베타 실서버 조건에서 추가하면 됨.

이 문서를 기준으로 구현 단계에서 컴포넌트·노출 조건·플로우를 구체 코드로 옮기면 됩니다.
